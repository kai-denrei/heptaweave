## Lessons
- **The "build a tuning UI, ship the locked values" workflow is a massive productivity win and should be the default for visual/generative work.** — from this session, 2026-05-20.
  - **What happened:** instead of guessing render constants and iterating with the user via screenshots, we built `scripts/tune.html` with 18 sliders + live preview + localStorage persistence. The user dialed in 14 parameters from their phone in a single short session and confirmed "this looks satisfying." Values were then hardcoded as the project-default tune layer.
  - **Why it worked:** the user got direct, low-latency feedback on changes (preview updates in real time). They had the FULL parameter surface available, not just the 3-4 knobs I would have guessed they cared about. Result: a satisfying lock-in that captured taste decisions across the whole renderer.
  - **How to apply:** for any future renderer with multiple interacting visual knobs, BUILD THE TUNER FIRST. The cost (a few hundred lines, half a day) is negligible compared to N rounds of "what about a bit more X / a bit less Y." Persist via localStorage so it survives reloads and works from any device.
- See [[dev]] Lessons for the engineering-side write-up of the same lesson + supporting lessons on canonical-renderer fidelity and headless-Chrome harnesses.

## Open Questions
- [x] ~~**TO-DO 1 — one-trait Cistercian:** per-digit continuity or one literal unbroken stroke?~~ RESOLVED 2026-09-03: neither — one unbroken trait grown radially from the centre of the stem, stem and four digits written simultaneously. See Decisions.
- [x] ~~**Digit 6 is the one shape the resolved spec does not cover.**~~ RESOLVED 2026-09-09: option (iii), own seed at the bar's midpoint, started when the stave front reaches its height. Built in `growthFront.js`. Every digit path attaches to the stave except 6, whose path is the far-side vertical bar (`[(2,0),(2,1)]`, mirrored per place) — it touches the stave nowhere, so a growth front rooted at the stem can never reach it. Any numeral containing a 6 (≈34% of 0–9999) therefore has at least one component that is unreachable, i.e. not one trait. Options: (i) add a connector along the digit's own quadrant edge so 6 hangs off the stave — changes the canonical glyph shape, which the project has refused to do before; (ii) let 6's bar appear as a deliberate detached mark — honest to the Cistercian standard but breaks "one trait" for a third of numerals; (iii) grow 6's bar from its own seed simultaneously, so it reads as part of the same gesture without being topologically connected. Proposal: (iii) — it preserves the canonical shape and the simultaneity, and "unbroken" then describes the gesture rather than the topology. Needs the operator's call before build.  — owner: claude-on-kainode — since: 2026-09-03
